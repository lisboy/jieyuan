# 出图硬约束（prompt guard）

构建工具把这里每个 `## guard:<key>` 段落里**代码块内的文本**原样拼进该角色的出图 prompt：
`guard:style` 前置给所有角色所有资产，`guard:child/teen/adult` 按角色 `age_band` 强制追加，任何角色数据都不能覆盖它。

目的有三个，都不允许 AI 自由发挥：
1. **可上架**：低龄向角色绝对不出现性感化表达。
2. **每张卡是不同的人**：81 张卡最容易死在"全都好看但全都一样"上，所以五官、发型、瞳色、记号、姿态、机位、辅色由 `content/identity.json` 逐人给定，`guard:style` 只负责强制"照给定值画，不许回落到通用美人脸"。
3. **像一款游戏**：画风、配色层级与背景画法由 `guard:style` 统一收口，六个势力各有自己的场景基调（`content/factions.json` 的 `artScene`）。

> 改 `guard:style` 等于改全套卡的画风：`npm run build` 会把新守卫刷进每份 prompt，
> `node tools/art-jobs.mjs` 会因此把所有已出图标记为**过期**，逐张重出即可，不需要人记得谁还没改。

## guard:style

```
国风精致二次元厚涂插画，高完成度商业手游卡面：颜色之间是细腻的渐变过渡与光影晕染，皮肤通透有润泽高光，头发一根根画出成束的高光带与透光边缘，织物有厚度与垂坠；绝对不要硬边平涂赛璐璐、不要纯色块填色、不要纸片剪影式的扁平插画、不要速涂草图感与干笔飞白、不要灰蒙的土黄低饱和调
光影是这张图的灵魂：一个明确的主光方向 + 一道强逆光或轮廓光把人物从背景里剥出来，逆光在发丝与织物边缘烧出一圈亮边；亮部带暖色泛光（bloom），空气里有雾感、体积光与光晕；暗部通透不糊死，整体像被真实光线照过而不是被上色工具填过；珠帘、水珠、金属、霜粒这类小件上要给出会闪烁的高光点
眼睛是画面焦点：大而有神，虹膜有层次（瞳孔深处渐变、上缘投影、下缘反光），长睫毛与眼线精细，眼周一点柔红；脸是柔和的明暗过渡，不是线条勾出来的平面
面孔纪律：这是插画不是照片——五官精致、皮肤抛光、比例偏二次元，但允许走近写实倾向的精致国风脸；不要真人照片质感、不要毛孔与胶片颗粒、不要 3D 渲染的塑料皮肤。男角色同样按这套精致度画，不许滑成写实硬汉
五官纪律（最重要）：发型、发色、瞳色、表情、辨识记号五项必须按下方【本角色识别】原样画出来，不许回落到通用的漂亮脸、不许自行把发型美化成默认长直发。同势力角色靠这五项区分，不靠名字
配色纪律（四层，缺一不可）：主色＝该角色六气代表色，用于服装最大色块；辅色＝该角色专属搭配色，用于腰带、袖缘、内衬、披帛、裙摆镶边等第二大面积，必须与主色形成看得出的撞色或深浅搭配；中性色＝米白与墨石，用于底色、鞋底、阴影；鎏金＝只出现在一两件小配饰上。全片不出现第五种彩色
背景纪律：背景是该角色【身份场景】的实景，不是纯色渐变。必须有三层景深（前景一小块虚焦、中景一处建筑或地形、远景压成单色剪影）与一个明确的时间光（黄昏斜阳 / 夜里灯火 / 雪后清晨 / 炉口火光 / 水下透光 四选一并贯彻全图）；背景的灯、烛、炉口、雪面反光要是真的发光体，给画面提供第二光源
人物必须是画面主体：半身图取腰上近景、全身图完整含足部且人物占画面高度 85% 以上，两种都要求脸部清晰可辨且落在画面上三分之一；绝对不要"很远的一个小人站在大风景里"，也不要把人物画成背景剪影的一部分
背景与人物如何共存：细节集中在人物轮廓之外，人物正后方约 30% 宽度保持低对比；背景整体饱和度低于人物；飘落物（花瓣、雪、火星、气泡、水珠）作为虚焦前景压在画面边角与上半，允许它多，但每一片都必须是失焦的柔和光斑而不是清晰的小图形；建筑与器物可以做主体光源的遮挡物，不排满画面，不画符文刻纹与地面发光法阵
人物与背景必须分得开：给一条清晰的轮廓光，人物主光方向与背景时间光方向一致
构图纪律：景别、画幅、人物在画面中的位置、镜头角度与姿态全部取自下方【本资产构图】，不同资产不许共用同一个居中直立站姿；无论哪种构图，都按上一条保证人物是主体
非人角色（兽灵/兔灵/羽灵/鲛灵/剑灵/器灵）：耳形、毛色、尾数、翅形、角必须清楚可辨，不得表现为戴发饰的人类；兽毛要画出蓬松的毛束与透光边缘，翅膀要画出羽片层次，不能画成平滑的色块
材质质感：毛皮蓬松、织物有绣纹与褶皱重量、金属配饰反光、木质与石质带风化痕迹——观众应能摸出这身衣服是什么做的
无文字、无水印、无边框、无 LOGO、无 UI 元素、无卡牌边框
```

## guard:child

```
明确稚气面部比例（大眼短脸圆下巴），身形矮小于其他角色，服装厚实完整（宽袖学袍/厚袄/连帽加长裤），不显示身体曲线，无腰身剪裁、无暴露、无媚态姿势，动作为日常事务（扫地/抱瓮/递物/抬头看），不允许湿身透视与伤痕
下半身一律长裤或及踝长袍，腿部不裸露，不赤足，只穿布鞋或短靴
```

## guard:teen

```
不得性感化：无深胸开口、无透视材质、无撩发媚态、无湿身贴体、无赤足
下半身一律长裤或及踝长裙，腿部不裸露；鞋只允许平底布鞋与短靴，绝不出现高跟鞋、凉鞋与腿部绑带
名册里的"短打/短襦/小褂/小袄"一律指上半身的短夹克式上衣，必须搭配长裤，不得理解成短下装
服装为门派制式（学袍/短打加长裤/素裙加长裤/甲片），最多露出手腕与脚踝
```

## guard:adult

```
允许成熟剪裁（长裾/束腰/披氅/甲胄/深领）与冷峻或妩媚气质，但不得裸露、不得内衣外穿、不得性暗示姿势；成熟靠剪裁、材质与神情，靠的是贵气不是露
```

## 兽灵（beast: true）

必须写清物种：耳形 + 毛色 + 尾数/翅形。禁止把兽灵处理成"戴发饰的人类"。
**数量本身就是身份**：七尾就是七尾，出图模型默认会往九尾画，所以 prompt 里明确"严格按文本数字，一条不许多画"。

## 配色系统

- **主色**取角色所属六气的代表色（`content/elements.json` 的 `color`），由 `build.mjs` 写成 prompt 的"主色"一行。
  这样 81 张卡放在一起时，颜色本身就是元素识别码：看到青木绿就知道是青木系，不需要靠文字。
- **辅色**取 `content/identity.json` 里该角色的 `accent`，是逐人给定的第二大面积色——它承担"这身衣服好不好看"的一半，
  也承担"这两张卡不是同一个人"的证据。辅色不许等于主色，也不许同势力内重复（`validate.mjs` 判错）。
- 中性色固定为米白与墨石，鎏金只出现在小件配饰上——它是"贵气"的记号，不是第三个主色。

## 一人一套识别

`content/identity.json` 给每个角色七项：`hair`（发型发色）、`eyes`（瞳色眼形）、`expr`（表情气质）、
`mark`（辨识记号）、`pose`（姿态与机位）、`accent`（辅色）、`prop`（主道具）。
这七项 + `roster.json` 的 `art.set/outfit/motif` 一起构成一张卡的全部视觉身份；prompt 里没有的，模型就会自己发挥成通用脸。
