## 三、产品定位与设计支柱

**一句话**：仙侠收缘卡牌——你抽到的不是卡，是一段缘。

四条设计支柱（所有新系统必须至少命中一条）：

1. **缘为核心**：羁绊/双修/因缘剧情做成战斗强度的一部分（差异化壁垒）。
2. **立绘即主角**：每张稀有度 ≥ SR 的立绘都"活着"（呼吸/视差/出场演出）。
3. **随手可玩，周周有奔头**：挂机兜底日活，赛季/塔/活动给周目标。
4. **操作有质感**：任何按钮按下必须有反馈（音效占位+位移+光效），重大操作有仪式交互。

## 四、美术方案

### 4.1 立绘"伪 3D"化（本方案最高优先级亮点）

用户点名要 3D 效果。基于现有 2D 全身立绘，三档方案：

**方案 A：程序化分层视差 + 呼吸感（P0，零额外美术成本，81 人全覆盖）**

- 把单张立绘拆成 3 层渲染：`背景虚化层(角色身后) / 主体层 / 前景飘带发丝层`。
  - 拆层用 AI 抠图（rembg 或生成时直接出"主体+透明底"两版），管线里加 `portrait_fg.png`；拆不出的角色退化为单层+整体视差。
- Unity 侧新组件 `PortraitStage`（替代裸 Image）：
  - 三层按 z 排布，透视相机下随指针/摇杆做 ±2° 视差摆动（阻尼跟随）；
  - 呼吸：主体层 `scale.y = 1 + 0.008·sin(t·1.2)`，发丝层 `y 位移 ±3px`，SSR 以上叠加衣摆 0.5Hz 慢摆；
  - 出场：从景深外推进（scale 1.15→1.0 + 透明度 + 位移缓动 0.6s）；
  - 稀有度氛围：UR 脚下光圈+周身粒子，SSR 逆光边缘光（shader 描边发光）。
- 立绘尺寸升格：名册详情/主城看板位/UP 池页头 使用 60% 屏高的 `PortraitStage`。

**方案 B：AI 图生视频动态立绘（P1，SR 以上逐步覆盖）**

- 用现有立绘跑图生视频（每角色 2 秒循环：衣摆/发丝/呼吸），抽帧成 sprite sequence 或直接 mp4 + `VideoPlayer` 循环播；
- 用于：UP 池页头、角色详情页、大招演出插入帧。管线台账加 `motion` 一类，按周补 5-10 张。

**方案 C：图生 3D 低模（P2 观望）**

- Tripo/Meshy 类图生 3D 出 Q 版手办摆件，用于**洞府家园陈列**与主城看板（旋转展示台），不做战斗模型（质量不可控、绑定成本高）。

**卡面 3D 交互**：所有卡牌 UI 统一换成 `Card3D` 组件——悬停跟随指针做 ±8° 倾斜（伪厚度：双层 Image+阴影），点击翻牌用真实 `transform` 3D 翻转（现有抽卡翻牌升级），长按放大出细节。

### 4.2 战斗表现升级（从"剪影对砍"到"舞台剧"）

- **战场**：斜 45° 透视地面（程序化云雾+地贴+接引光柱），我方左 3×2 松散站位、敌方右，单位脚下椭圆接触阴影；
- **单位**：换用全身立绘 `PortraitStage` 迷你版（已有真图 81/81），待机呼吸、受击后仰、死亡碎裂淡出（按六气颜色粒子化）；
- **演出分级**：
  - 普攻：弹道+命中闪白（已有）+ hit-stop 40ms；
  - 技能：半屏 Cut-in（角色名+技能名竖排毛笔字+六气底纹，0.5s）；
  - 大招：全屏暗幕 + 大招立绘推进（39 张真图）+ 缺图回退伪 3D 立绘（方案 A 保证 81 人都有演出）+ 镜头推拉；
  - 合击技（新）：指定缘对同时在场且能量满 → 双立绘同屏 Cut-in，专属演出。
- **打击反馈**：屏幕边缘六气色晕影、暴击时镜头 punch + 时间 0.2 倍 120ms、连击计数浮字。

### 4.3 UI 视觉语言重铸（气质：纸墨仙缘）

- **材质系统**（一次做好全屏复用）：宣纸米白 `#F2EAD8` / 玄墨 `#1A1522` / 朱砂红 / 鎏金描边；面板=宣纸纹理+墨色晕边（程序化生成 9-slice），按钮=玉质感圆角+鎏金细描边+按压下沉；
- **字体层级**：标题用毛笔感字体（霞鹜文楷/站酷小薇体，免费商用，打包进 StreamingAssets），正文系统雅黑；字号阶梯 60/40/28/22/18；
- **布局骨架**：所有二级页统一「左侧竖排页签(卷轴样式) + 右内容区 + 顶栏全局货币条」，告别每屏自定义摆位；
- **主城改"场景"**：不再按钮排排坐——主城即一幅斜视角仙山画卷：中立绘看板娘(方案A)+悬浮功能建筑（缘阁=抽卡/藏书院=名册/演武场=出征/百宝囊=行囊/坊市=商城，建筑即按钮，带待机动画），底部卷轴抽屉收纳二级功能；
- **稀有度表达升级**：卡面边框做"材质差异"（N 素纸/R 青竹/SR 紫檀/SSR 鎏金/UR 琉璃流光 shader），角标改为印章篆字（缘/珍/稀/世/绝）。

## 五、UI/UX 与交互规范（操作不能只是图标）

**全局交互法则**（写进 UiTheme，一处实现全屏生效）：

| 交互 | 规范 |
|---|---|
| 按钮按压 | 缩放 0.96 + 变暗 10% + 程序化"墨点"音效（按稀有度换音高）；禁用态置灰+锁图标+原因气泡 |
| 页面切换 | 统一转场：旧屏淡出 0.15s → 新屏"卷轴展开"0.25s（遮罩动画），禁止瞬切 |
| 弹窗 | 两段式：暗幕淡入 + 面板从 1.06 弹回 1.0（backOut）；关闭必给取消路径 |
| 重大操作仪式感 | 抽卡=拉缘签（签筒晃动→抽出一支签→签化光散出卡）；合成升星=双指聚气按压 0.8s 蓄力圈；突破=印章"落印"动画 |
| 信息提示 | Toast 顶部统一队列；数值变动飘字（+500 鎏金上飘）；货币不足直接跳转获取途径弹窗 |
| 长按/悬停 | 卡牌长按 0.4s 放大 1.4 倍出属性浮窗；图标长按出说明 tooltip（统一组件） |
| 手势 | 编队槽位拖拽换位；列表侧滑快捷操作 |
| 引导 | 首次进入新系统自动聚焦遮罩+毛笔手势指引（可跳过） |

**新增全局组件清单**：`UiAnim`（缓动库，自写 200 行 Tween）、`Card3D`、`PortraitStage`、`CutIn`、`RitualHold`（蓄力圈）、`Toast`、`ToolTip`、`ScreenFader`（转场）。

## 六、核心循环与系统设计

### 6.1 战斗系统深化

- **六气相克**：金水木火土+雷（沿用现有 elements），克+30%伤 / 被-15%；界面标注克制箭头；
- **阵型**：5 槽分前 2 后 3——前排受击权重 ×2、有减伤 15%；后排远程射程加成；拖拽换位（P0 上拖拽交互）；
- **速度轴**：改为 ATB 时间轴（顶部行动条可视化），速度决定出手频率，取代纯轮转；
- **能量与合击**：普攻+25 能量、受击+10；100 能量可放大招；缘对(羁绊)同时满能量 → 可选"合击"（威力 1.6 倍单体特效升级）；
- **词条驱动**：法宝套装改变技能行为（如"惊雷4件：大招附带感电"）——后期深度来源。

### 6.2 养成线（六维深度，拉开长线目标）

| 养成 | 消耗 | 上限 | 解锁 |
|---|---|---|---|
| 等级 | 修行散页/批注/残卷（已有） | 100 | 初始 |
| 突破 | 洗髓丹+阶级突破材料（已有） | 每 20 级一档 | 通关 1-4 |
| 技能 | 技能书（已有） | 每技 10 级 | 初始 |

### 6.3 抽卡与获取

- 池子类型：**常驻缘池 / UP 缘池（80 抽必出 UP，50% 概率歪常驻）/ 阵营池 / 新手池（20 折+首十必出 SR+）**；
- 保底沿用 51 软/80 硬；UP 池独立歪计数继承到下个 UP（大保底机制）；
- **缘签抽取仪式**（替代点按钮翻卡）：签筒→抽签→签文闪现稀有度色→化光展开成 Card3D，十连一键+逐张跳过；
- 定向残卷保留（已验证好设计），UP 池歪掉的 UR/SR 自动+1 定向券。

### 6.5 战斗外循环（防"下线即无事可做"）

## 七、现时活动与运营框架

### 7.1 常驻框架

- **签到**：7 日循环（第 7 天送抽卡券）+ 月历大签（月累计 21 天送 UR 自选签）；
- **仙令战令**：50 级免费轨+进阶轨，周任务刷活跃，赛季 4 周；免费轨也给高价值（皮肤染色/缘签券），进阶轨放动态立绘/专属头像框；
- **七日迎新**：登录送自选 SR + 40 抽 + 满练度过渡装；第 7 天任务送自选 SSR；
- **兑换码/邮件**：通用领取中心（公告条可点开）。

### 7.2 赛季与 UP 排期（上线首月示例，基于现有 39 张大招立绘角色做 UP）

- **节日模板**：中元/中秋/新年三大模板，复用"活动币商店+剧情节点+专属装饰"结构，只换皮与数值；
- **回流**：7 天未登录 → 回归礼包+专属双倍 3 天+一次自选 SR 直取。

## 十一、风险与裁剪原则

1. **体量风险**：12 玩法全做 ≈ 数月工作量。铁律：P0 不验收不开 P1；每模式先出"最小可玩版"（如肉鸽先 1 幕 15 分钟）。
2. **美术产能**：动态立绘/抠图按周补录，稀有度从高到低覆盖（UR→SSR→SR），N/R 永久用方案 A 程序化。
3. **数值风险**：所有新数值进 config 表 + JS 对拍，禁止双端手写。
4. **技术风险**：不引重型插件（Live2D SDK/商业 UI 框架），全部程序化自研，保持"零外部依赖"现状。
5. **裁剪原则**：任何系统若三周做不出最小闭环 → 降级或砍掉（万象棋局即此类预裁剪项）。
