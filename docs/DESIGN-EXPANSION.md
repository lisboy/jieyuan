## 0. 诊断：现在缺的不是系统，是「变化」

### 0.1 家底（这些是设计的原材料）

| 维度 | 现状 | 对设计的含义 |
|---|---|---|
| 关卡 | **1000 关**（8 手工章 + 2 自动章 × 100 关），12 个历练副本（4 类 × 3 难度），**200 层**登仙塔 | 内容量已经够，缺的是「关与关之间的差异」 |
| 角色 | 81 人 / 6 势力 / 6 气 / 7 定位，全身立绘 81 张 | 每张卡都撑得起一条支线、一套命格 |
| 羁绊 | **19 组**（势力 6 + 六气 6 + 定位 7），经 `tools/lib/bonds.mjs` 折算成 `atk/hp/spd/crit` 乘数、与缘器合并进同一条 `allyTeam[].bonus` 通道；`ult` 文案只做演出 | 设计支柱「缘」在战斗里目前只等于一个乘数 |
| 战斗引擎 | ATB + 能量 + 护盾分层 + 修饰符（层数/回合/衰减）+ 触发式被动 + 六气克制 + 波次 + 星级判定 | 原语很全，缺的是「把这些原语用在不同关卡上」 |
| 剧情 | 65 个节点，绑在关卡前/后自动播 | 只服务主线；81 张卡里 80 张没有自己的故事 |
| 经济 | 铜钱/缘玉/心神/残卷/尘缘/技能书 + 散页/注记/残卷/洗髓丹 | 结构健康，缺「周目标」与「长线货币」 |

### 0.2 九个具体缺口

| # | 缺口 | 证据 |
|---|---|---|
| D1 | **长线目标真空** | `tools/lib/meta.mjs:372` 的成就表写死于 `stagesCleared>=96`、`tower>=30`、`stars>=144`；现在是 1000 关 / 200 层 / 3000 星，第 96 关之后**没有任何里程碑** |
| D2 | 塔的产出断头 | `stages.json` 的 tower 只有首通奖励；200 层爬完 = 该玩法从此零产出 |
| D3 | 羁绊只在乘数里 | `tools/lib/bonds.mjs` 只读 `bonds.json` 的 `bonus`（atk/hp/spd/crit），`serve.mjs:540-544` 把它并进 `allyTeam[].bonus`；19 组的 `ult.name/desc` 没有任何代码消费，C# 里也搜不到合击逻辑 |
| D4 | 战斗全自动 | 前端注释「战斗演出 = C# 引擎的回合事件回放（倍速/跳过）」；玩家唯一决策点是编队与养成，六气克制存在但**无法主动利用** |
| D5 | BOSS 只有数值 | boss 与 normal 的差别只有 `mod: [12]` + 3 波 + 更高稀有度，没有机制 |
| D6 | 剧情只挂在关卡上 | `story.json` 节点只有 `id/chapter/stage/when/title/lines`，没有选择、没有个人线、没有回看面板 |
| D7 | 运营完全空白 | 全仓库 `战令/赛季/周常/活动/邮件/兑换码/竞技场` 命中 0；只有 `daily.login` 一个签到领奖 |
| D8 | 缘器无 build | 4 槽只有主属性 + 固定副词条 + 等级 + 突破，没有套装/重铸/器纹 |
| D9 | 材料单向 | 散页 → 注记 → 残卷只能刷，不能转化；卡等级时只能等体力 |

**一句话**：引擎能力（12 种 fx、触发事件、护盾分层、六气克制）已经够写一款有深度的卡牌，但关卡、养成、剧情都还没把这些能力用起来。本方案只做「原语的再组合」，新增引擎能力控制在 3 处。

## 1. 设计前提（不能破的）

1. **铁律不回退**：内容只改 `content/`，战斗数值只在 `src/Shiyuan.Core`，经济只在 `tools/lib/game.mjs`。
2. **沿用现文立场**：`economy.json` 明写「不做日常任务清单，也不想让玩家打卡」；`gacha.json` 明写「不做错过就没了」。所有活动设计必须满足这两条。
3. **新增引擎能力只有 3 处**：合击施法、BOSS 阶段触发、韧性/破防。其余全部落在 `content/` 数据 + `game.mjs` 结算 + 前端渲染。
4. **单人可维护**：任何系统若三周做不出闭环 → 降级或砍掉（沿用总纲 §11）。
5. **明确不做**：实时手动战斗（要把「一次请求算完整场」改成逐回合协商，架构成本过高）、真联机、万象棋局、仙盟 26 人、Live2D。

## 2. 战斗：让同一批敌人打出不同的局

### 2.0 现有原语清单（写新玩法前先看清手里有什么）

| 原语 | 位置 | 可以直接拿来做什么 |
|---|---|---|
| ATB 时间轴 | `SkillExecutor.AtbThreshold` + `TickSpan(spd)` | 速度差、减速/加速类词条 |
| 能量 0~100 + 大招 | `Unit.Energy/EnergyCap` | 合击、耗能词条、开局能量 |
| 护盾分层 | `Unit.ShieldLayers` + `ShieldUp` | 吸伤、破盾触发 |
| 修饰符（stat/op/value/turns/maxStacks/decays） | `Unit.AddModifier` | 几乎所有 buff/debuff |
| 触发式被动（on 事件） | `PendingTrigger` + `SkillExecutor.Raise` | 阶段技能、连携、反击 |
| 六气克制（两环，跨环中性） | `BattleMath.ElementMult` | 破防判定、元素反应 |
| 波次 + 波间回血 | `StageScript.waveRecover` | BOSS 分段、换场 |
| 星级判定（回合数/无死亡/血量） | `stages.json starRules` | 挑战目标、评价 |

### 2.1 天时（关卡词条）——成本最低的内容放大器

**玩法**：每关开战前显示 0~3 条「天时」（战场条件），例如：

| 词条 | 效果 | 用在哪 |
|---|---|---|
| 灵气稀薄 | 我方能量获取 ×0.7 | 普通关（0 条起，逐步出现） |
| 雷池 | 紫雷伤害 +40%，敌方紫雷单位开局 +20 能量 | 雷系章节 |
| 瘴 | 每 3 回合全体 3% 最大生命 dot | 云岫/海国章 |
| 铁壁 | 敌方防御 +25%、韧性 +50% | 配合 §2.3 破防 |
| 孤军 | 只能上阵 4 人，掉落 +30% | 高难关卡（自选风险） |
| 灯灭 | 治疗量 -40%，护盾 +40% | 反治疗队 |
| 疾风 | 全体速度 +20%，受击伤害 +10% | 快攻拉扯 |
| 双生 | 同波同名敌人共享 30% 伤害 | 逼迫点杀 |

**为什么适合本项目**：
- 敌人、美术、关卡本体全部复用——只加一张词条表，1000 关立刻有了「这次不一样」。
- 词条全部落在现有修饰符原语里（`buff/debuff` + 全局施加），C# 只需在 `StageScript` 初始化时把词条转成 `Unit.AddModifier`，零新机制。
- 抽取必须确定性：按关卡 id 的 seed 取（与现有 `Request.seed` 同一套），否则回归夹具失效。

**落点**：新增 `content/mods.json`（词条表）；`stages.json` 每个 `kind` 配「词条条数」（normal 0 / elite 1 / midBoss 1 / boss 1 + 固有 1 / 塔每 10 层 +1，上限 3 / 活动 2~3）；`meta.mjs` 展开时按 seed 抽进 `StageDoc.mods`；`Core/StageScript` 读取并施加；前端在关卡情报条 + 战斗顶栏显示。

**数值锚**：每条词条给 +12% 铜钱与材料掉落；高难档（劫余）默认 2 条。词条不得影响首通缘玉（首通奖励恒定，避免「刷词条」）。

**验收**：同一关同 seed 词条恒定；10 条词条全部能在战斗顶栏被看见；开关词条后同一编队的胜率变化 ≥10%（说明真的影响了局）。

### 2.2 BOSS 阶段脚本——一个能力，三处复用

**玩法**：BOSS 血量跌破 70% / 40% 时进入下一阶段：换招式表、触发一次场地效果、播一句台词。例如炉主：

- 阶段一：单体重击 + 自身叠护甲；
- 阶段二（<70%）：全场「炉火」dot，改成 AoE 喷火；
- 阶段三（<40%）：每回合召唤一只炉吼（复用现有小怪），自身攻击 +30%。

**为什么适合本项目**：`StageScript` 已经是「一波一波打」的节奏器，加阶段检查只是多一次阈值判断；`SkillExecutor.Apply` 已能施放任意 fx 表。这个能力一次写好，主线关主、塔每 5 层、世界妖王、活动 BOSS 全部受益。

**落点**：`stages.json` 展开时，`kind: boss/midBoss` 的关卡写入 `phases: [{ at: 0.7, fx: [...], line: "..." }, ...]`（fx 用现有 schema，含 `summon` 需要新增一种 `k:"summon"`）；`StageScript.Step` 每片检查阈值 → 走 `SkillExecutor.Apply/Raise`，事件 `kind:"phase"`。前端播 Cut-in + 台词气泡（复用现有 `who=小怪 id` 的说话人通道）。

**数值锚**：阶段触发不额外加数值，只换招；每多一阶段，该 BOSS 首通奖励 +1 档（缘玉 +25%）。**不叠加**：同一关最多 3 阶段。

**验收**：塔 5 层的关主能靠「拖到第三阶段再爆发」和「抢在第二阶段前秒掉」两条路通过；`npm run core` 回归夹具覆盖阶段触发。

### 2.3 韧性·破防——让「克制」和 `break` 定位有手感

**玩法**：每个单位多一条韧性条（默认看不见，精英/BOSS 显示在血条下）。

- 命中削韧：普通 -6、克制元素 -18、`role: break` 角色 -25、群攻对每个目标 -4；
- 韧性归零 → **破防 2 回合**：受伤 +20%、速度 ×0.8、不能放大招、我方全队 +15 能量；
- 每回合自然回韧 +8；破防结束后本场韧性上限 -25%（最多两次，防无限破防）；
- 双向生效：敌方 `break` 定位怪也能破我方前排的防。

**为什么适合本项目**：`elements.json` 的克制关系已经算在伤害里，但玩家感知不到「我克制了它」。破防把克制从「+30% 伤害」变成「打穿 → 集火窗口」，同时让目前最没存在感的 `role: break`（6 个角色）有不可替代的职责。实现上只是 `Unit` 加一个数值 + 一个 `Lock("break")`，复用现有修饰符与锁定体系。

**落点**：`Unit.Toughness/AddToughness`；`SkillExecutor` 的 `damage` 分支里按命中方式削韧；`elements.json` 不动；`stages.json` 给精英/BOSS 一个 `toughness` 系数；前端加一条细韧性条 + 破防状态图标（已有状态图标组件）。

**数值锚**：韧性上限 = `60 + 敌方等级 × 1.2`（Lv1 → 61，Lv80 → 156）。以满级队打 Lv80 精英为例：普通输出约 20 回合破一次防，克制队约 7 回合——这就是「带对元素」的可见回报。

**验收**：战报里能看到「破防贡献伤害占比」；同编队换一个克制元素后，塔 40 层的回合数下降 ≥15%。

### 2.4 合击——把「缘」从文案变成战斗强度

**玩法**：同羁绊（`bonds.json`）的两人同时在场上、能量都 ≥60 时，可发动合击：

- 消耗两人各 60 能量，每场每对 1 次（缘值 5 级后 2 次，见 §3.1）；
- 威力：单体向 ≈ 单人满大 ×1.6；群向 ≈ ×1.2；
- 附带一条「缘」效果：`破防 +30 韧性` / `全队 +20 能量` / `给目标上 mark` / `治疗 + 护盾`——由每组羁绊的 `ult` 决定；
- 战斗内默认由「战术偏好」自动释放（§2.6），不要求实时操作。

**为什么适合本项目**：19 组羁绊的 `ult.name/desc` 已经写好了（「紫电同鸣」「万灵同声」……），现在只差 `fx`。数据侧只是给每组羁绊补一张 fx 表；引擎侧加一个 `ComboCast(main, partner, skillDoc)`，内部复用 `SkillExecutor.Apply` 两次（主位施法 + 副位补一段）。这是**唯一能把「缘为核心」这条设计支柱落到战斗数字上的机制**，也是抽卡差异化的支点。

```jsonc
// bonds.json 每条羁绊追加
"ult": {
  "name": "紫宸照影·星落成章",
  "energy": 60,
  "fx": [
    { "k": "damage", "coef": 1.6, "type": "magic", "target": "enemy_single" },
    { "k": "buff", "stat": "crit", "op": "add", "value": 0.1, "turns": 2, "target": "ally_all" }
  ]
}
```

**落点**：`bonds.json` ×19 补 `ult.fx`；`Core/SkillExecutor` 加 `ComboCast`；`BattleLoop` 在大招判定处加「是否可合击」；**注意合击不能走 `bonus` 通道**（`lib/bonds.mjs` 那个通道只传乘数），要作为技能表单独下发；`validate.mjs` 校验 fx 里的 stat 必须在 `StatFields` 内、target 在已有枚举内；前端加双人 Cut-in（复用已有大招立绘 + 抠图）。

**验收**：19 组合击全部可跑；同一队伍换羁绊后，木桩伤害结构明显不同（战报里合击单独一项统计）；无合击可发动时不得卡住回合。

### 2.5 六气反应——只做三组，做深不做多

**玩法**：同一目标在 2 回合内被两种相克元素命中 → 触发反应（每目标每回合最多 1 次，不叠加）：

| 组合 | 反应 | 效果 |
|---|---|---|
| 沧水 + 紫雷 | 感电 | dot 20% 攻击 ×2 回合，期间被击韧性 -10 |
| 离火 + 青木 | 燃薪 | dot 逐回合递增（8% / 16% / 24%） |
| 曜光 + 素月 | 晦明 | 治疗 -50%，2 回合 |

**为什么只做三组**：六气两环（形：火木水 / 神：光雷月），只取「相邻相克」三对，规则一句话能讲清；六气两两组合 15 种会让战斗阅读成本爆炸。这也让「混色队」第一次有存在意义，而不只是同色加成。

**落点**：`elements.json` 增 `reactions` 表；`Unit` 记 `lastElement + lastTurn`；`SkillExecutor` 在 `damage` 结算后判定；反应伤害在战报里单独统计。

**验收**：反应伤害在战报中占比可查；三组反应各有一次可复现的回归用例。

### 2.6 战术偏好（战前指令）——替代「实时手动」的正确做法

**玩法**：开战前设三个偏好，存进存档、随 `battleRequest` 下发，由引擎按偏好自动决策：

| 偏好 | 选项 |
|---|---|
| 大招时机 | 攒满就放 / 留到首领波 / 只在队友 <40% 时放 |
| 合击 | 见首领即用 / 见 3 人以上用 / 不用 |
| 集火 | 残血优先 / 最高攻优先 / 均摊 |

**为什么这么做而不是实时手动**：现在的架构是「一次请求算完整场、返回回放」。做实时手动要把协议改成逐回合协商，等于重写 `serve.mjs` 的战斗通道和前端演出循环。而「战前偏好」只是给 `battleRequest` 多带三个枚举，决策仍在引擎里（符合「战斗数值只在 C#」的铁律），却把玩家从「只能看」变成「可以布置」。

**落点**：`BattleContract.Request` 加 `tactics`；`SkillExecutor` 选目标时读偏好；`save.tactics`；前端编队页加三个开关（默认值 = 现在的行为，保证老存档一致）。

**验收**：同一编队切换偏好后，塔 30 层胜率或回合数变化 ≥15%；默认偏好下所有现有回归夹具结果不变。

### 2.7 战报与失败诊断——零引擎成本，感知最强

**玩法**：每场战斗结束后可看「战报」：

- 伤害构成饼：普攻 / 技能 / 大招 / dot / 合击 / 反应；
- 时间轴：每一波、每次大招、每次破防、每次死亡；
- 失败诊断（规则文案）：如「第 2 波被 AoE 收掉 3 人：站位集中且无护盾」；
- 「抄作业」：把编队 + 关卡 id + 偏好生成一段可分享配置。

**为什么零成本**：`BattleContract.Response` 已经返回 `turns[]`（含每回合 `events` 与 `state`），前端也已经在消费它做演出。战报只是把同一条数据用另一种方式画出来。

**落点**：纯前端（`web/app.js` + 新面板样式）；诊断文案规则表放 `content/diagnostics.json`，由前端按事件序列匹配。

**验收**：任意一场失败都能点开战报并读到「为什么输」；战报数据与演出数据来自同一份 response，不得二次计算。

### 2.8 第六人（候补）——给「抽到新卡」一个位置

**玩法**：编队 5 人 + 1 候补。主队有人阵亡时候补自动登场（0 能量、不继承 debuff），登场时全队 +10 能量。

**为什么**：现在抽到第 6 张好卡只能替换——玩家没有「都要」的空间。候补位给的是「编队策略」而不是数值：把谁放候补、什么时机上场，都是决策。

**落点**：`stages.json teamSlots` 保持 5，新增 `benchSlots: 1`；`battleRequest` 加 `bench`；`StageScript.StartWave` 处理「场上存活 < 上阵数 → 候补补位」；前端编队页 6 格。

**验收**：编队 6 格可用；「5 人全灭但有候补」能继续战斗；`test-web.mjs` 编队测试覆盖。

## 3. 培养：让「人」有分支，而不只是数值

### 3.1 缘值（羁绊等级）——把「缘」做成长期养成

**玩法**：每个角色 0~10 级缘值。

| 来源 | 数值 |
|---|---|
| 随队出战（胜利） | +1 / 场（该角色每日上限 5） |
| 赠送「见缘帖」 | +3 |
| 看完一段因缘传记 | +10 |
| 主城来访者打招呼 | +5 |

等级奖励：1/2/4/7/10 级各 +1% 攻击与生命（合计 5%）；**3/6/9 级解锁传记章节**；**5 级解锁第二次合击**；10 级解锁专属台词与称号。

**为什么**：这是全案里唯一同时串起「培养 + 剧情 + 战斗」的系统——看传记涨缘值，缘值强化合击，合击改变战斗。而且它把「抽到重复卡」的挫败转成「这个人跟我更熟了」。数据只在 `save.bonds`，不需要新美术。

**落点**：`save.bonds: { [id]: level }`；`bonds.json` 保留原加成，缘值作为额外通道；`game.mjs` 加 `bondExp/bondLevel`；前端在角色详情 + 羁绊页显示。

**验收**：满缘值角色的合击伤害比 1 级高 25%；缘值来源与上限全部走 config。

---

### 3.2 共鸣（练度保底）

**玩法**：队伍中「第 5 高等级」作为共鸣线，其余角色可免费同步到该等级（同步不返还突破材料，也不享受等级上限外的突破加成）。

**为什么**：卡牌游戏最常见的劝退是「练错卡」。共鸣让抽到的新卡立刻能进二队，同时不破坏「练 5 个主力」的核心循环——这也是剑与远征验证过的结构。

**落点**：`game.mjs` 计算有效等级时加一层（展示为「共鸣 Lv」）；`maxLevel` 不动；C# 的 `Member.level` 由服务端下发，天然生效。

**验收**：Lv1 新卡可立刻上场且数值正确；14 天模拟里「因练错卡而卡关」的天数归零。

---

### 3.3 命格（三选一的天赋盘）

**玩法**：每人 6 格，每格 3 选 1（攻 / 守 / 缘三条线），可免费重置（每周 1 次免费，之后 5000 铜钱）。

| 格 | 类型 | 示例 |
|---|---|---|
| 1 / 2 / 4 / 5 | 小数值 | +3% 攻击 / +4% 生命 / +5 能量效率 / +2% 暴击 |
| 3 / 6 | 行为改变 | 大招 +1 目标 / 普攻额外 +5 能量 / 受击反弹 10% / 治疗溢出转护盾 / 首次死亡免疫 |

材料「星砂」：塔每 10 层 1 颗、活动 3 颗、周目标 2 颗。

**为什么**：总纲把命格定位成「星铁行迹位」，本方案的关键差异是**只在大格给行为改变**——小格给数值，保证不会「不看攻略就废号」；大格给机制，保证同一角色有两种玩法。这是「深度」与「可读性」的平衡点。

**落点**：新增 `content/constellations.json`（按 `role` 模板 + UR 专属格）；`save.constellation[id]`；解锁后作为永久 fx 注入 `Unit`；前端角色详情加一页。

**验收**：同一角色两套命格在塔 30 层形成两条通关路径；重置不丢已投入的星砂。

---

### 3.4 器纹与重铸——给缘器一个 build

**玩法**：

- 每件缘器 1 个器纹位，4 种 kind 各 3 种纹（刻纹消耗「纹砂」：活动 / 塔 / 器魂合成）；
- 同纹 2 件 → 小效果（该件主属性 +6%）；同纹 4 件 → 大效果：
  - 兵刃：暴击伤害 +25%
  - 法宝：护盾 +20%
  - 灵饰：首回合能量 +20
  - 道袍：受伤 -8%
- 重铸：器魂重投主属性，10 次内必出一档更高（pity）。

**为什么**：现在缘器只有「换件」，没有「配装」。器纹把 4 槽从「凑主属性」变成「围绕一个纹组 build」，同时给活动产出一个有长期价值的消耗口（纹砂）。

**落点**：`tools/lib/equip.mjs` 加 `RUNES` 表 + `engrave/reforge`；`save.equips[uid].rune`；前端缘器详情加纹位。

**验收**：4 兵刃 vs 4 法宝在同一角色身上伤害差 ≥8%（证明 build 有意义）；重铸 pity 有回归用例。

---

### 3.5 心法（技能改造）

**玩法**：每个技能 2 选 1 改造，切换只花铜钱（不耗材料，鼓励试）：

- 大招：群攻化（倍率 ×0.65 但打全体）/ 追加 dot / 能量消耗 -20；
- 被动：触发条件放宽 / 数值提高但持续 -1 回合。

**为什么**：解决「角色练到顶就没事做」，并让老角色有二次利用。数据上是给 `roster.json` 的 skill 加一张 `runes` 表，引擎侧仍是同一套 fx，只是换参数。

**落点**：`roster.json` skills 增 `runes`；`SkillExecutor` 读玩家选中的 variant；`validate.mjs` 校验每个 variant 的 fx 合法。

**验收**：先做 UR/SSR ≥10 人；同一角色两套心法在战报里的伤害构成不同。

---

### 3.6 觉醒（UR 的终点）

**玩法**：UR 角色满星 + 突破满 + Lv80 → 三步觉醒任务：塔 100 层首通 / 提交该角色专属缘器 +15 / 看完该角色 3 段传记。奖励：真名大招（替换 fx 一档 + 名字变色）、立绘染色（复用现有立绘做换色，不新增原图）、专属称号。

**为什么**：抽卡游戏需要一个「值得追」的终点，但不能靠加第二套数值。觉醒把「塔 + 缘器 + 剧情」三条线收束到一个目标上，奖励是**表现 + 一档技能**，不是又一层等级。

**落点**：`content/awaken.json`；`save.awaken[id]`；C# 读觉醒态替换技能表。

**验收**：UR 觉醒前后同一场战斗伤害提升 12%~18%（可解释，不失控）。

---

### 3.7 材料转化与拆合

**玩法**：3 散页 → 1 注记（每日 10 次，无损）；注记 2 → 1 残卷（有损 50%）；跨系统（残卷 ↔ 器魂）5:1 走尘缘。

**为什么**：`economy.json` 已经承认「卡等级的是经验物而不是铜钱」。转化是给玩家一条「把囤积换成本命」的路，也是对「抽卡不出货」的情绪补偿。

**落点**：`economy.json` 加 `conversions` 表；`game.mjs` 结算；前端行囊页。

**验收**：14 天模拟里「因缺一种材料而卡等级」的天数下降 ≥30%。

---

### 3.8 一键继承

**玩法**：缘器换人时保留全部强化与器纹，花当前价值 10% 的器魂。

**为什么**：现在换队 = 重练一套缘器，这是隐性的「不敢换卡」。继承让编队实验变便宜，直接提升抽卡价值。

**落点**：`equip.mjs` 加 `transfer(uid, fromChar, toChar)`。

---

### 3.9 成就 / 图鉴档位重排（最便宜的长线修复）

**玩法**：成就档位按现规模重排：

- 主线：每 100 关一档（100/200/…/1000），最后一档「万象归一」= 1000 关；
- 星级：每 300 星一档（300/600/…/3000）；
- 塔：每 20 层一档（20~200）；
- 行为型：无死亡通关 100 关 / 单关 10 回合内通关 50 次 / 集齐一个势力全员。

**为什么**：这是 D1——现在 96 关就发「通关全部主线」。这不是新增系统，是把已有的表按新体量重写，**半天工作量，收益最大**。

**落点**：`tools/lib/meta.mjs buildAchievements`（改为按 `stagesSpec` 实际规模生成，禁止写死 96/30/144）；`AchievementService.ValueOf` 增加 `noDeath`/`fastClear` 统计（需要 `save.stats` 新增两个写入点）。

---

## 4. 剧情：让 81 张卡各自有故事

### 4.1 因缘传记（个人线）

**玩法**：每人 3 段（缘起 / 纠缠 / 了断），条件：拥有该角色 + 缘值 3/6/9。奖励：缘值 +10、专属残卷 2、卡面染色。

**为什么**：`story.json` 的播放器、`who` 通道、存档「播过没有」的机制全都现成；内容只是同结构的 nodes。81 人 × 3 段 × 8 行 ≈ 1900 行文本，是纯文本产能，不依赖美术（立绘已有）。先做 39 个有大招立绘的 UR/SSR。

**落点**：新增 `content/bios.json`（与 `story.json` 同 schema，加 `char` 字段）；`serve.mjs` 直接读（不构建）；前端名册详情加「因缘」页。

**验收**：随机 5 个角色能读完 3 段并拿到缘值；`who` 为角色 id 时自动用其头像/立绘。

---

### 4.2 抉择与三条缘痕

**玩法**：每章末尾一个抉择点（3 选项），记一个倾向：**系 / 断 / 观**。影响：章末独白不同 + 下一章一个持续被动（系：治疗 +3%；断：伤害 +3%；观：能量 +5）。

**为什么**：`story.json` 加 `choices` 数组 + `save.flags` 即可，不需要分支剧情树（只影响一段独白和一个 buff）。玩家第一次在剧情里有「我决定了」的感觉，而成本接近零。

**落点**：`story.json` 节点加 `choices: [{ text, flag }]`；`save.flags`；前端播放器加三个按钮。

**验收**：三条倾向各有一条独白与一个被动；选择可回看、不可重复刷 buff。

---

### 4.3 物志（敌人与场景条目）

**玩法**：每个敌人击败 1 / 10 / 50 次解锁三段条目；集齐一个势力区域给缘玉 + 图鉴档。

**为什么**：`mobs.json` 现有 **47 只敌人**，每只已有单行 `lore` 与三技能命名，扩成三段是「把已有资产二次变现」；同时给「重复刷本」一点收集意义。

**落点**：`mobs.json` 加 `lore[3]`；`save.defeats[id]`；前端图鉴加「物志」分页。

---

### 4.4 缘痕图谱

**玩法**：把剧情里出现的人 / 物 / 势力做成节点，随剧情解锁连线，形成一张可缩放的缘痕关系图。

**为什么**：数据全部来自 `roster/factions/bonds/story`，零新文本；纯前端 SVG 力导向布局（经典脚本里写一个小型 layout，约 200 行）。它是全游戏最容易被截图传播的一屏，也是「缘」这个主题最直观的视觉表达。

**落点**：纯前端 `web/app.js` + 一个 `graph` 面板；节点解锁条件读 `save.story`。

---

### 4.5 章末回望

**玩法**：每章 100 关完成 → 播章末节点 + 评价面板（三星率 / 无死亡关数 / 使用角色 TOP3 / 用时）→ 章节奖励（缘玉 + 一张章末 CG，用现有 boss 立绘）。

**为什么**：1000 关如果不做包装，就是一条无限长的进度条。章末回望把「第 100 关」变成「这一章结束了」，也让 10 个章节各有结尾。

**落点**：`story.json` 已有章末节点；前端加一个 `chapterSummary` 面板；奖励走 `economy.json` 新表。

---

### 4.6 主城来访者

**玩法**：主城看板位每天随机 1 个已拥有角色，说一句话（复用 `voice.json` 台词池 / `bonds` 文案风格），点一下打招呼 → 缘值 +5。不点也不损失（不打卡）。

**为什么**：主城现在是一个功能入口，不是一个「地方」。来访者是成本最低的「世界活着」的感觉，且与缘值/传记同源。符合 `economy.json` 的反打卡立场：给的是额外好感，不是每日必做。

**落点**：`save.visitor { key, id, greeted }`；`content/visits.json`（按角色写 3~5 句）；前端主城看板位。

---

## 5. 活动：给 1000 关之后一个「时间结构」

### 5.1 活动作用域（先做框架，再办活动）

**玩法**：活动 = 一个 JSON 作用域：

```jsonc
// content/events/yaochao-1.json
{
  "id": "yaochao-1", "label": "妖潮·雪魅",
  "startAt": "2026-11-01T04:00:00+08:00", "endAt": "2026-11-08T04:00:00+08:00",
  "currency": "event:yaochao",
  "stages": [...],            // 复用 StageDoc，进 meta.dungeons 之外的独立作用域
  "shop": [...],              // 复用 economy.shopBuy 的结构
  "story": [...]              // 复用 story 节点 schema
}
```

**为什么**：所有活动本质都是「关卡 + 商店 + 日程 + 剧情」，一次把作用域做好，之后每个节日只写内容。这也避免「每办一次活动改一次 serve.mjs」。

**落点**：`content/events/*.json`；`build.mjs` 展开为 `meta.events`；`save.events[id]`；前端加「活动」入口（常驻，未开始时空状态）。

---

### 5.2 妖潮（7 天限时活动本）

**玩法**：6 关递增链 + 每日 3 次「妖潮」无限波（60 秒或全灭结算，按伤害档位发活动币）。商店：限定头像框 / 缘器券 / 星砂 / 纹砂 / 染色。

**为什么**：无限波复用现有引擎（只要不断刷波次），是「比谁打得深」的天然排行榜玩法，且不需要新战斗机制。

**数值**：活动期间总产出约 900 币，商店总价 1200 币（缺一点，鼓励打满但不逼）。

---

### 5.3 仙令（赛季通行证，但不打卡）

**玩法**：4 周赛季，任务池 40 条，**完成任意 24 条即可满 50 级**；经验来自所有玩法（推图 10/关、塔 20/层、妖潮 30/次、论道 20/次）；免费轨给抽卡券/铜钱/染色，进阶轨给动态立绘框/专属称号。

**为什么**：`economy.json` 反对每日打卡，但长线又需要目标。解法是「任务池 + 累计经验 + 不每日清零」：玩家可以周末一口气补完，不必每天上线。这条与总纲的「周任务」有冲突，本方案选择「尊重现文立场」，因为单人开发最怕的是维护一堆每日重置。

**落点**：`content/pass.json`（赛季 + 任务池 + 奖励轨）；`save.pass { season, exp, claimed }`；经验在 `settleStage` 里按玩法类型累加。

---

### 5.4 世界妖王（异步全服 BOSS）

**玩法**：每周 1 只（6 个 boss 立绘轮转），每周 3 次挑战，累计伤害分 4 档发奖；全服进度用种子模拟文案（「全服已削去 37%」）。

**为什么**：不需要真联机，但给出「集体在打一只怪」的感觉。数据上是「一个特殊关卡 + 一个伤害记录」，成本很低。

**落点**：`content/worldboss.json`（轮转表 + 血量系数）；`save.worldboss { week, dmg, tries }`；前端一个血条 + 档位表。

---

### 5.5 论道会（异步镜像 PVP）

**玩法**：玩家存「防守队快照」，挑战者用自己队伍打 AI 镜像；段位 7 档（青铜→登仙），赛季 4 周结算；PVP 系数单独（伤害 ×0.85、治疗 ×0.85、血量 ×1.25）。

**为什么**：引擎已经支持「我方 + 敌方队伍」跑完整场，镜像 PVP 只是把敌方队伍换成另一名玩家的快照。这是本方案里唯一需要认真做平衡的系统——所以**先做「试炼镜像」**（打一组预设队伍）验证数值，再开真 PVP。

**风险与裁剪**：若两周一幕做不出闭环，降级为「每周一组高难镜像挑战」，不做段位。

---

### 5.6 七日迎新与回归

**玩法**：7 日表（第 7 天十连券）；回归礼包（7 天未登录 → 3 天双倍 + 自选 SR）。

**为什么**：`save.daily.login` 机制已在，只是扩成 7 日表与一个离线天数判断。这是留存性价比最高的两个功能。

---

### 5.7 活动经济规则（写死，不许破）

1. **不绝版**：活动商店在结束后 4 周并入常驻兑换，活动币永不清零（与 `gacha.json poolRules` 一致）。
2. **不产主线必需材料**：活动只产星砂/纹砂/染色/头像框——避免「不打活动就卡关」。
3. **长线货币**：每个活动至少产 1 种长线货币（星砂或纹砂），保证活动结束后玩家仍有理由记得它。

## 6. 优先级与依赖

| 梯队 | 内容 | 为什么先做 | 依赖 |
|---|---|---|---|
| **一（1~2 周，低成本高回报）** | 成就档位重排（§3.9）、战报诊断（§2.7）、天时（§2.1）、章末回望（§4.5）、来访者（§4.6）、材料转化（§3.7）、共鸣（§3.2）、七日签到（§5.6）、活动作用域 + 妖潮（§5.1/5.2） | 全部是「已有系统按现规模补齐」，不加新机制 | 无 |
| **二（核心深度，3~6 周）** | 合击（§2.4）、BOSS 阶段（§2.2）、韧性破防（§2.3）、缘值（§3.1）、命格（§3.3）、器纹（§3.4）、因缘传记（§4.1）、仙令（§5.3） | 决定「这游戏有没有深度」的四件事：合击、破防、命格、传记 | 命格/器纹依赖星砂/纹砂产出（塔/活动） |
| **三（长线）** | 六气反应（§2.5）、第六人（§2.8）、心法（§3.5）、觉醒（§3.6）、世界妖王（§5.4）、论道会（§5.5）、缘痕图谱（§4.4） | 锦上添花，且 PVP 需要单独平衡 | 觉醒依赖塔 100 + 传记 |

**不要并行**：命格 / 器纹 / 心法三条养成线同时开会让人看不懂——按「命格 → 器纹 → 心法」逐版本开。

## 8. 风险与裁剪
