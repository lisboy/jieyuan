## 五、技能平衡

### 5.1 稀有度阶梯（输出定位终式伤害系数均值）

绿 1.20 < 蓝 1.59 < 紫 1.61 < 金 2.03 < 红 2.34（PASS：随稀有度递增，允许 5% 个体波动）。

### 5.2 同阶内角色差异（本轮修复）

原实现的问题：紫/蓝/绿三档是模板装配，每个定位只有 1~3 个招式变体，导致同稀有度同定位的一整组角色**共用同一个终式名和同一个倍率**（最多 6 人同名同强度），本档 `audit-balance` 报 5 条 WARN。

本轮修改：
1. `content/skill_templates.json`：每个定位的终式模板从 1~3 个扩到 4~7 个，机制各不相同（单体重击 / 多段 / 附带减速 / 附盾 / 群疗 / 嘲讽 / 群控 / 充能……）。
2. `tools/build.mjs`：模板卡按角色 id 选终式模板变体；如果同稀有度+同定位已经有人用了这一招，就顺延到下一个变体——**招式名与机制始终成套**，同组不会重名也不会撞机制；同时给终式系数加 ±6% 的个体偏置（`hash(charId)` 决定），同组角色的倍率不再一模一样。
3. `tools/gen-vfx-variants.mjs`：普攻/终式变体组合改为按「同稀有度+同定位」优先分配不同组合，避免两个同定位角色还是同一套演出。
4. `tools/audit-balance.mjs`：同阶差异核验排除小怪/妖王（它们按设计克隆名册角色的技能组，不应算作「角色缺少特色」）。

结果：`audit-balance` 的 5 条 WARN 全部消除，硬性判据全部 PASS；同时稀有度阶梯仍单调递增（个体偏置 ±6% 不破坏阶梯）。

### 5.3 各角色技能特色

- 128 个角色每个都有独立的终式演出名（`ultName` 128/128 唯一，PASS）。
- 每个角色都有独立的普攻变体（8 套铺满）和终式变体（8 套铺满）。

## 六、技能与普攻特效差异化（本轮修复）

发现的问题：`content/vfx.json` 早就为每个角色算好了 `variants.ult`（u1~u8）和 `variants.byChar.ultName`，`web/js/battle.js` 也把 `ultVariant` / `ultName` 传给了演出层，但 `web/js/battle-fx.js` 的 `ultBarrage()` **从未读取这两个参数**——实战中所有角色的大招都只剩六气那一套通用演出，玩家看到的"每人特效不同"只存在于数据里。

修复：
1. `ultBarrage()` 新增 `variant` 分支：u1 镇纹 / u2 地裂 / u3 回旋 / u4 锁链 / u5 光柱 / u6 波纹 / u7 飞羽 / u8 预兆雷，作为**前置起势**叠在六气主演出之前（主演出保留，不替换）。
2. `ultBarrage()` 新增 `name` 渲染：终式演出名以题字形式显示在屏幕上方。
3. `web/style.css` 新增 8 套 `.ub-var-*` 动画 + `.ub-name` 题字样式（全部纯 CSS，无新依赖）。
4. 普攻链路此前已读 `atkVariant`（`attackCombo` → `ATK_VARIANT` 8 套），本轮确认保持。
5. `tools/gen-vfx-variants.mjs` 重排分配：同稀有度+同定位优先用不同 (attack, ult) 组合（128 人 30 种组合，同组 0 撞车）。

jsdom 逐变体验收：u1~u8 全部生成对应 DOM 节点（u7 飞羽 21 片），演出名正确、六气主特效同时存在；无变体的旧路径不产生 `ub-var-*`（向后兼容）。

浏览器目视核对（`target/shots/`）：
- `vfx-u2.png`：u2「裂」——一道横向裂纹横贯三个目标卡位，题字「裂云惊雷」正常显示。
- `vfx-u7.png`：u7「羽」——细羽错落分布在三个目标卡位，题字「漫天细羽」正常显示。
- `vfx-u4f.png`：u4「缚」——锁链环收束在目标卡位上，题字「九尾·齐开」正常显示。
三张均无 JS 报错（预览页底部自检行 `ultBarrage=function / anchors=3` 正常）。

## 八、遗留与建议

- `validate.mjs` 的 101 条「技能为模板装配，待人工润色」是既有设计（模板文本刻意保持可用但不讲究），本轮未扩大该范围；如需全部手写文案，可按 `polish_note` 清单逐条润色。
- 小怪/妖王按设计克隆名册角色技能组，不参与同阶特色核验；若后续希望小怪也有独立技能，需要改 `tools/lib/mobs.mjs` 的克隆策略。
